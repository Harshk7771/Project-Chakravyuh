Project Chakravyuh

NEXT-GENERATION AUTONOMOUS SOC ARCHITECTURE · MADE IN INDIA

Project Chakravyuh is an enterprise-grade, fully autonomous Security Operations Center platform built on 100% open-source technologies. Named after the legendary multi-layered military formation from the Mahabharata, it delivers concentric layers of detection, monitoring, and automated response.

ℹ Platform Philosophy
Chakravyuh believes that advanced security operations should not be exclusive to large enterprises. This platform is free for Indian Defence, LEA, and Intelligence Agencies — and value-priced for the private sector.
What is Chakravyuh?

Chakravyuh is a unified SOC platform that replaces the need for separate SIEM, EDR, SOAR, Threat Intelligence Platform (TIP), and Digital Forensics tools. It provides a single-pane-of-glass view across your entire security infrastructure.

Step 1 — Clone the Repository
bash · terminal
# Clone Project Chakravyuh
git clone https://github.com/your-org/chakravyuh.git
cd chakravyuh

# Verify the release signature
gpg --verify chakravyuh-v1.0.0.tar.gz.sig
Step 2 — Configure Environment
bash · .env configuration
cp .env.example .env
nano .env

# Required environment variables:
CHAKRAVYUH_SECRET_KEY="your-secure-secret-key"
VIRUSTOTAL_API_KEY="your-vt-api-key"

bash · docker compose

# Verify all containers are running
docker compose ps

Quick Start

Get your first alert flowing through Chakravyuh in under 15 minutes.

1. Connect a Log Source

Navigate to Settings → Log Sources → Add Source. Chakravyuh supports Syslog, Windows Event Forwarding, Filebeat, and cloud-native log connectors.

filebeat.yml · endpoint agent config
output.logstash:
  hosts: ["chakravyuh-server:5044"]
  ssl.enabled: true

filebeat.inputs:
- type: winlog
  event_logs:
  - name: Security
  - name: System
  - name: Microsoft-Windows-Sysmon/Operational
2. Enable Detection Rules

Go to Detection → Rule Manager. Enable the built-in Sigma rule packs:

  • Windows Endpoint Detection (847 rules)
  • Linux System Monitoring (412 rules)
  • Network Intrusion Detection (238 rules)
  • Ransomware Behavioral Indicators (94 rules)
  • MITRE ATT&CK Coverage Pack (Complete)
3. Configure Your First Playbook

Navigate to Automation → n8n Playbooks → New Playbook. Use the built-in template "Critical Alert → Auto-Contain → Assign Analyst".

ℹ Playbook Logic
Chakravyuh automatically assigns cases to analysts based on CVSS score: CVSS 9.0+ → L2/L3, CVSS 7.0–8.9 → L1 Analyst, CVSS <7.0 → Queue. This reduces manual triage by ~70%.

Chakravyuh follows a defense-in-depth model with six concentric layers of detection and response — mirroring the Chakravyuh military formation.

Data Flow

Events flow from sources (endpoints, network devices, cloud) through a normalized ingestion pipeline into OpenSearch. The correlation engine applies Sigma rules and ML models to generate alerts. Alerts are enriched with threat intelligence and scored. High-severity alerts trigger automated n8n playbooks for containment and case creation.

Detection Rules

Chakravyuh uses Sigma rules as the detection backbone, providing vendor-agnostic, human-readable detection logic that can be audited and modified.

sigma rule · ransomware volume shadow deletion
title: Ransomware Shadow Copy Deletion
status: stable
level: critical
detection:
  selection:
    CommandLine|contains:
      - 'vssadmin delete shadows'
      - 'wbadmin delete catalog'
      - 'bcdedit /set recoveryenabled no'
  condition: selection
falsepositives:
  - Legitimate backup software

EDR Platform

Chakravyuh EDR provides continuous endpoint visibility, behavioral detection, and automated response — without requiring a commercial agent.

Agent Deployment
bash · deploy wazuh agent (linux)
curl -so wazuh-agent.deb https://packages.wazuh.com/4.x/apt/pool/main/w/wazuh-agent/wazuh-agent_4.7.0-1_amd64.deb

WAZUH_MANAGER='chakravyuh-server' \
WAZUH_AGENT_GROUP='chakravyuh-endpoints' \
dpkg -i ./wazuh-agent.deb

systemctl enable --now wazuh-agent
Response Actions
  • Isolate endpoint from network (block all traffic except SOC)
  • Kill malicious process by PID
  • Quarantine file by hash
  • Capture live memory image with Volatility integration
  • Collect forensic artifacts (logs, prefetch, registry hives)
  • Force password reset for compromised accounts

Digital Forensics

Automated evidence acquisition, chain-of-custody preservation, and investigation report generation — built for both field analysts and court-admissible evidence.

Evidence Acquisition

When an endpoint is flagged, Chakravyuh automatically triggers the acquisition pipeline, capturing memory, disk artifacts, network state, and process information in a timestamped, cryptographically-signed evidence bundle.

Report Generation

The report generator produces initial investigation reports in three formats. All reports include executive summary, technical IOC listing, timeline graph, affected asset inventory, and analyst recommendations.

ℹ Supported Formats
PDF (court-ready, digitally signed), DOCX (editable for analyst notes), XLSX (IOC spreadsheet for further analysis and sharing with CERT-In).

Case Assignment Logic
n8n · case assignment pseudocode
IF cvss_score >= 9.0 AND asset_criticality == "CRITICAL":
  assign_to("L3_ANALYST"), notify("CISO"), escalate("INCIDENT")
ELIF cvss_score >= 7.0:
  assign_to("L2_ANALYST"), sla_timer("4h")
ELIF cvss_score >= 4.0:
  assign_to("L1_ANALYST"), queue("STANDARD")
ELSE:
  auto_close_with_note("LOW_RISK")

SpiderFoot OSINT Engine

Automated open-source intelligence chaining — pivots across 200+ data sources to build relationship graphs between IPs, domains, threat actors, email addresses, and leaked credentials.

Why SpiderFoot?

Commercial tools like Maltego charge per-transform and require a desktop client. SpiderFoot is fully open-source, self-hostable, and integrates via REST API — making it the ideal OSINT engine for a sovereignty-aware SOC platform. When a Chakravyuh alert fires on a suspicious IP or domain, SpiderFoot is invoked automatically to build the full intelligence picture.

What SpiderFoot Chains Together
Starting EntitySpiderFoot DiscoversUse in SOC
Suspicious IPASN, hosting provider, blacklist hits, related domains, open ports, geolocation, historical WHOISThreat actor attribution
Malicious DomainRegistrant email, DNS history, co-hosted domains, certificate fingerprints, Pastebin leaksC2 infrastructure mapping
Email AddressBreach databases, social profiles, dark web leaks, affiliated usernamesInsider threat / credential compromise
File Hash (SHA256)VirusTotal hits, AV detections, malware family, related samplesMalware campaign correlation
Company / Org nameExposed assets, leaked documents, employee data, attack surfaceAttack surface discovery
Integration with Chakravyuh
⚡ Automatic OSINT on Every High-Severity Alert
When an alert crosses SRS ≥ 7.0 (High band), Chakravyuh automatically triggers a SpiderFoot scan on the alert's source IP and any associated domains, and attaches the relationship graph to the case file.

GreyNoise Intelligence

Separates internet background noise from targeted attacks — instantly tells analysts whether a suspicious IP is scanning the entire internet or specifically targeting your infrastructure.

The Problem GreyNoise Solves

Without GreyNoise, a typical SOC wastes 40–60% of triage time investigating Shodan crawlers, Censys scanners, and security research bots that trigger alerts on every internet-facing IP. GreyNoise tags these as "benign background noise" automatically, so analysts focus only on IPs that are actually targeting your organisation.

Classification Types
GreyNoise TagMeaningChakravyuh Response
MALICIOUSIP is actively attacking systems, confirmed by GreyNoise sensorsAlert priority upgraded; SRS score boosted
UNKNOWNIP not observed in GreyNoise sensor networkStandard investigation workflow
BENIGNKnown scanner/researcher — internet background noiseAlert auto-deprioritised; analyst notified
Integration

GREYNOISE_AUTO_ENRICH="true" # enrich every inbound IP alert

Malware Analysis

Automated malware classification combining static analysis (YARA, PE headers, strings), dynamic sandboxing, and 10M+ signature databases.

Classification Engine

When a suspicious file is detected, Chakravyuh submits it to a multi-stage analysis pipeline that classifies it by malware family within seconds.

Supported Malware Categories
  • Ransomware — File encryption behavior, shadow deletion, ransom note creation
  • Trojan / RAT — Persistence, C2 communication, keylogging patterns
  • Worm — Self-propagation, SMB/network spreading behavior
  • Spyware — Screenshot, audio capture, credential harvesting
  • Rootkit — Kernel-level hiding, hook detection
  • Adware / PUA — Low-risk classification
